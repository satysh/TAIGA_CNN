# Random Forest feature combination experiment

## Назначение ноутбука

`random_forest_feature_combination_experiment.ipynb` — автономный эксперимент для задачи классификации событий `gamma` / `proton` на очищенных/model Hillas-данных. Ноутбук перебирает комбинации разрешённых признаков, обучает для каждой комбинации несколько `RandomForestClassifier` с разным числом деревьев и сохраняет метрики качества в CSV.

Этот Markdown-файл является сопровождающим описанием ноутбука. Если логика ноутбука или список признаков меняются, этот файл нужно обновлять вместе с ним.

## Что происходит по шагам

1. **Импорты и прогресс-бары.** Загружаются `numpy`, `pandas`, инструменты `scikit-learn`, `itertools`, `math` и `tqdm`. Если `tqdm` недоступен, используется небольшой fallback-класс с выводом прогресса в stdout.
2. **Настройки эксперимента.** Задаются smoke-test режим, размер сэмпла, `RANDOM_STATE`, сетка `N_ESTIMATORS_GRID`, размер тестовой выборки, положительный класс `gamma` и путь для CSV с результатами.
3. **Пути к данным.** Указываются CSV-файлы с очищенными/model Hillas-данными для gamma и proton. Если в текущей notebook-сессии уже есть датафрейм `df` с колонкой `label`, он используется вместо чтения CSV.
4. **Загрузка данных.** Gamma и proton объединяются в один датафрейм по общим колонкам; для gamma выставляется `label = 0`, для proton — `label = 1`.
5. **Нормализация таргета.** Ноутбук ищет колонку класса (`particle_type`, `class`, `target`, `label`, `y`), нормализует значения к строкам `gamma` и `proton` и сохраняет их в `target_particle`.
6. **Подготовка признаков.** Создаются служебные признаки `amount`, `obs_date`, `camera_color`, `telescope_id`, `energy`. Для физических/image-признаков создаются стабильные имена `length`, `width`, `alpha`, `size`: если таких колонок нет напрямую, ноутбук пытается взять значения из известных alias-колонок вроде `length[0]`, `width[0]`, `alpha[0]`, `size[0]`.
7. **Жёсткое ограничение списка признаков.** В обучение допускаются только признаки из раздела ниже. Все остальные колонки исходного датафрейма исключаются из `selected_features` и не участвуют ни в одной обучающей комбинации.
8. **Сэмплирование.** В `SMOKE_TEST=True` берётся воспроизводимый стратифицированный сэмпл до `SMOKE_TEST_SIZE`; если стратификация невозможна, используется обычный случайный сэмпл.
9. **Генерация комбинаций.** Строятся все непустые комбинации разрешённых признаков. При 9 разрешённых признаках максимум составляет `2^9 - 1 = 511` комбинаций; каждая комбинация обучается для каждого значения из `N_ESTIMATORS_GRID`.
10. **Pipeline обучения.** Для числовых колонок используется `SimpleImputer(strategy="median")`, для категориальных — `SimpleImputer(strategy="most_frequent")` и `OneHotEncoder(handle_unknown="ignore")`. Затем обучается `RandomForestClassifier`.
11. **Оценка качества.** Для каждой пары «комбинация признаков + число деревьев» считаются `accuracy`, `precision` и `recall` для положительного класса `gamma`.
12. **Сохранение результатов.** Итоговая таблица сохраняется в `RF Feature Selection Demo - Results.csv`, затем выводятся лучшие строки по `accuracy`, `precision` и `recall`.

## Разрешённые признаки для обучения

### Искусственные/служебные

- `amount`
- `obs_date`
- `camera_color`
- `telescope_id`
- `energy`

### Реальные физические/image-признаки после клининга

- `length`
- `width`
- `alpha`
- `size`

## Важные ограничения текущей версии

- В `selected_features` попадают только 9 признаков из списка выше.
- Любые другие поля исходных CSV, включая дополнительные Hillas-признаки, идентификаторы, target-колонки и служебные поля, не передаются в `X_all` и не участвуют в `RandomForestClassifier`.
- Признак `energy` сейчас создаётся искусственно по классу (`gamma` получает `1.0`, `proton` — `10.0`), поэтому он содержит намеренную утечку таргета. Это важно учитывать при интерпретации метрик.
