# Формат бинарных файлов `taiga*_st2b`

Документ описывает **фактический формат чтения**, который используется в проекте для файлов:

- `input/taiga607_st2b`
- `input/taiga623_st2b`

Основано на реализации парсера `CorsikaData` (`corsikadata.py`).

---

## 1) Порядок байт и типы

- Порядок байт: **little-endian**.
- Используемые базовые типы:
  - `int32` — 4 байта
  - `float64` (double) — 8 байт

В Python это соответствует шаблонам `struct.unpack('<i')`, `struct.unpack('<d')`, и т.д.

---

## 2) Общая структура файла

Файл состоит из последовательности событий без дополнительной «шапки» файла:

```text
[event_0_header][event_0_pixels]
[event_1_header][event_1_pixels]
...
[event_k_header][event_k_pixels]
```

Где:

- Размер заголовка события: **180 байт**
- Размер одной записи пикселя: **28 байт**
- Количество пикселей события хранится в самом заголовке (`N_pixels`), поэтому длина события переменная.

---

## 3) Бинарный layout события

### 3.1 Заголовок события (180 байт)

Смещение в байтах от начала заголовка:

| Смещение | Размер | Тип | Поле |
|---:|---:|---|---|
| 0 | 4 | int32 | `N_run` |
| 4 | 4 | int32 | `N_scattering` |
| 8 | 4 | int32 | `N_telescope` |
| 12 | 4 | int32 | `N_photoelectrons` |
| 16 | 8 | float64 | `energy` |
| 24 | 8 | float64 | `theta` |
| 32 | 8 | float64 | `phi` |
| 40 | 8 | float64 | `x_core` |
| 48 | 8 | float64 | `y_core` |
| 56 | 8 | float64 | `z_core` |
| 64 | 8 | float64 | `h_1st_interaction` |
| 72 | 8 | float64 | `particle_type` |
| 80 | 8 | float64 | `xmax` |
| 88 | 8 | float64 | `hmax` |
| 96 | 8 | float64 | `x_telescope` |
| 104 | 8 | float64 | `y_telescope` |
| 112 | 8 | float64 | `z_telescope` |
| 120 | 8 | float64 | `x_offset` |
| 128 | 8 | float64 | `y_offset` |
| 136 | 8 | float64 | `theta_telescope` |
| 144 | 8 | float64 | `phi_telescope` |
| 152 | 8 | float64 | `delta_alpha` |
| 160 | 8 | float64 | `alpha_pmt` |
| 168 | 8 | float64 | `T_average` |
| 176 | 4 | int32 | `N_pixels` |

Эквивалентно Python-распаковке:

- первые 16 байт: `'<4i'`
- следующие 160 байт: `'<20d'`
- последние 4 байта: `'<i'`

### 3.2 Запись одного пикселя (28 байт)

| Смещение | Размер | Тип | Поле |
|---:|---:|---|---|
| 0 | 4 | int32 | `amplitude` |
| 4 | 4 | int32 | `row_number` |
| 8 | 4 | int32 | `column_number` |
| 12 | 8 | float64 | `average_time` |
| 20 | 8 | float64 | `std_time` |

Эквивалентно Python-распаковке:

- первые 12 байт: `'<3i'`
- последние 16 байт: `'<2d'`

---

## 4) Семантика полей, важная для чтения

### `N_pixels`

- Количество пикселей текущего события.
- После заголовка нужно прочитать ровно `N_pixels` записей по 28 байт.

### `particle_type`

- Используемая в проекте интерпретация:
  - `1.0` → gamma → метка `1`
  - `14.0` → proton → метка `0`
- Значение хранится как `float64`.

### `row_number`, `column_number`

- Это координаты пикселя в центрированной системе камеры.
- В текущем проекте пиксель кладётся в матрицу 27×27 как:

```python
img[row_number + 13, column_number + 13] = amplitude
```

Следовательно, ожидаемый рабочий диапазон индексов до сдвига обычно `[-13, +13]`.

---

## 5) Минимальный алгоритм чтения (язык-независимый)

1. Открыть файл в бинарном режиме.
2. Пока можно прочитать 180 байт заголовка:
   1. Распаковать заголовок (4×`int32`, 20×`float64`, 1×`int32`).
   2. Взять `N_pixels`.
   3. Цикл `N_pixels` раз:
      - читать 28 байт
      - распаковать (3×`int32`, 2×`float64`)
      - использовать `amplitude`, `row_number`, `column_number` (время опционально).
3. Конец файла.

Проверка целостности: если при чтении заголовка/пикселя пришло меньше ожидаемого числа байт, файл обрезан или повреждён.

## 6) Рабочий Python-пример для студента

```python
import struct

HEADER_SIZE = 180
PIXEL_SIZE = 28


def read_st2b(path):
    events = []

    with open(path, 'rb') as f:
        while True:
            hdr = f.read(HEADER_SIZE)
            if not hdr:
                break
            if len(hdr) != HEADER_SIZE:
                raise IOError('Broken file: incomplete event header')

            n_run, n_scattering, n_telescope, n_photoelectrons = struct.unpack('<4i', hdr[:16])
            dvals = struct.unpack('<20d', hdr[16:176])
            n_pixels, = struct.unpack('<i', hdr[176:180])

            event = {
                'n_run': n_run,
                'n_scattering': n_scattering,
                'n_telescope': n_telescope,
                'n_photoelectrons': n_photoelectrons,
                'energy': dvals[0],
                'particle_type': dvals[7],
                'n_pixels': n_pixels,
                'pixels': [],
            }

            for _ in range(n_pixels):
                p = f.read(PIXEL_SIZE)
                if len(p) != PIXEL_SIZE:
                    raise IOError('Broken file: incomplete pixel record')

                amplitude, row, col = struct.unpack('<3i', p[:12])
                avg_t, std_t = struct.unpack('<2d', p[12:28])
                event['pixels'].append({
                    'amplitude': amplitude,
                    'row': row,
                    'col': col,
                    'average_time': avg_t,
                    'std_time': std_t,
                })

            events.append(event)

    return events
```

## 7) Как это связано с CNN-пайплайном в этом репозитории

В проекте после чтения бинарника делается:

- формирование изображения `27x27` из пикселей (`row+13`, `col+13`)
- фильтр по суммарному сигналу события: `sum(amplitude) > 120`
- фильтр «хорошего изображения» по соседним ярким пикселям (`amp > 7`)
- преобразование в формат тензоров `(N, 1, 27, 27)`

Это уже **не часть формата файла**, а правила подготовки данных для модели.

## 8) Справка по текстовому формату событий (для передачи студенту)

Ниже — краткая русская расшифровка полей, которую удобно дать студенту, если он работает с текстовым представлением событий (`*.txt`).

### Строка заголовка события (11 полей)

1. Номер события в симуляции CORSIKA.  
2. Номер рассеяния оси (`axis scattering`) — по сути номер копии события с изменённым положением оси (используется для увеличения выборки).  
3. `N` — число пикселей в событии.  
4. Энергия первичной частицы (ТэВ).  
5. `X`-координата оси ливня относительно телескопа (метры).  
6. `Y`-координата оси ливня относительно телескопа (метры).  
7. Зенитный угол телескопа (радианы).  
8. Азимутальный угол телескопа (радианы).  
9. Зенитный угол оси атмосферного ливня (радианы).  
10. Азимутальный угол оси атмосферного ливня (радианы).  
11. Атмосферная глубина максимума ливня (`Xmax`, г/см²).

### Строка пикселя (5 полей)

1. Номер кластера (пиксели организованы в кластеры по 28).  
2. Номер пикселя внутри кластера.  
3. `X`-координата пикселя в камере.  
4. `Y`-координата пикселя в камере.  
5. Амплитуда сигнала. Важно: амплитуда может быть отрицательной (из-за вычитания среднего уровня/pedestal).

> Примечание: разделы 1–7 выше описывают именно бинарный формат `st2b`, а этот раздел — эквивалентные физические поля в текстовом представлении событий.
