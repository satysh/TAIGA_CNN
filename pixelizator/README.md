# Pixelizator (multifile_honeygrid)

`pixelizator` — адаптивная анизотропная перепикселизация изображения из гексагональной камеры IACT в квадратную сетку с сохранением структуры ливня.

## Что делает алгоритм

Для каждого хита с координатами `(x, y)` и амплитудой `A`:

1. **Берётся локальная окрестность** радиуса `neighborhood_radius` (по умолчанию `7.5 см`).
2. **Считается взвешенный PCA** (веса = амплитуды соседних хитов).
3. Из PCA получаем:
   - угол главной оси: `theta = 0.5 * atan2(2*sxy, sxx - syy)`;
   - полуоси рассеяния: `sigma1 = sqrt(lambda1)`, `sigma2 = sqrt(lambda2)`.
4. Формируется **анизотропный эллипс влияния**:
   - `a = spread_factor * sigma1`;
   - `b = spread_factor * sigma2`;
   - оси ограничиваются снизу: `min_axis_size` (чтобы не вырождались в шуме).
5. Амплитуда распределяется по квадратной сетке (`square_bin_size`) через выбранную функцию веса и нормируется так, чтобы сумма амплитуд сохранялась.

## Функции веса

- `gauss` (по умолчанию): плавное гауссово затухание;
- `linear`: линейное убывание;
- `quad`: квадратичное убывание;
- `const`: постоянный вес внутри эллипса.

## Подходы, о которых часто спрашивают

### 1) Динамический радиус (`use_dynamic_radius`)

Вместо фиксированного окна для локального PCA используется:

`R = base + gain * log(1 + A_local)` с ограничением в диапазоне `[R_min, R_max]`.

Идея: у ярких хитов окно больше (больше контекста), у слабых — меньше (меньше влияния шума).

### 2) Глобальная ориентация (`use_global_orientation`)

Обычно угол `theta` берётся локально для каждого хита. В этом режиме:

- один `global_theta` считается по всему событию,
- затем используется для всех хитов вместо локальных углов.

Идея: снизить шумовые колебания направления; компромисс — хуже в сильно изогнутых/неоднородных событиях.

## Ключевые параметры

- `pixel_size = 1.5`
- `square_bin_size = 0.5`
- `neighborhood_radius = 7.5`
- `spread_factor = 1.5`
- `min_axis_size = 1.5`
- `weight_type = gauss | linear | quad | const`

## Что есть в `pixelizator_analysis.ipynb` (кратко)

Ноутбук повторяет ROOT-логику в Python и даёт быстрый цикл анализа:

1. Чтение входного txt-файла с событиями.
2. Конвертация одного события: hex-координаты → квадратная сетка.
3. Визуальное сравнение (scatter hex-центров vs heatmap квадратной сетки).
4. Проверка сохранения интеграла амплитуды.
5. Расчёт параметров Хилласа (`length`, `width`, `theta`) до/после конвертации.
6. Гистограммы распределений Хилласа.
7. Сравнение режимов: **base**, **global orientation**, **dynamic radius**.

## CLI-флаги ноутбука

- `--input-file`
- `--event-id`
- `--weight-type`
- `--use-global-orientation`
- `--use-dynamic-radius`

## Запуск ROOT-версии

Файл с данными должен быть в той же папке, что и макрос.

```bash
root -l multifile_honeygrid.cpp
```

После запуска создаются визуализации и txt-файлы в квадратной сетке (папка `fullfile`).

---

⚠️ При запуске ROOT-макроса в исходной версии есть предупреждение о потенциально резкой визуализации.
